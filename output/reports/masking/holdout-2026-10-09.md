## 合わせ込みの兆候(本番より大きく下がった細分)

1. **cued_number(−67.3pt)— 規則の無い文脈**: 手がかり語の一覧(`detect/lexicon.rs` の `CUED_NUMBER_CUES_JA`)が
   本番の画面に出る 6 語と同じで、ホールドアウトの「注文番号」「問い合わせ番号」「登録番号」「取引先コード」「契約番号」
   「会員No.」は対象外。手がかり語の直後に助詞が入る会話文(「会員番号は …」)も拾えない。検出できたのは本番と同じ手がかり語の 2 件だけ
2. **cue_value(−65.6pt)— 規則の無い文脈**: 手がかりが同じ観測の中・右隣・直下にある形だけを拾う。
   表の列の見出しにだけ手がかりがある形(「署名シークレット」の列。カタカナの語も一覧に無い)と「PIN」は対象外。
   会話文・コマンド内の英字の手がかり(`client_secret:` 等)は拾えている
3. **person_ja(−48.6pt)/ person_en(−46.0pt)— 辞書に無い**: 見逃した 19 人(日本語 12・英字 7)はすべて、敬称・ラベル・読み仮名が無い位置
   (名刺の大きな氏名、組織図の箱、チケット一覧の依頼者、「内部メモ ·」の後ろ)にあり、姓が辞書に無い。
   英字の名前は辞書がローマ字の日本人名だけのため、欧米系の名前は辞書の規則では拾えない。
   「同じページの別の出現」(f)は、手がかりから見つけた名前(「担当:」の後の名前 → チャットの発言者欄)では
   効いていたが、起点が無い名刺・組織図では働かない。「氏名・担当者の列」(h)はホールドアウトに該当する表が無く、評価できていない。
   【仮定】実在の人物と重ならないよう、ホールドアウトの日本語の姓は珍しいものを多く選んだ(15 人中、辞書にある姓は 2 人)。
   一般的な姓の分布より不利な条件なので、下がり幅はやや大きめに出ている可能性がある
4. **company(−33.3pt)— 規則の無い文脈**: 会社の種類に無い法人(一般社団法人)、名前の先頭がひらがなの後置の社名
   (ひらがなを助詞とみなして名前の前半を切る)、前置の種類の後に空白を含む英字の名前が続く形。後の 2 つは
   一部だけ覆う(部分一致)
5. **random_string(−25.8pt)— 規則の無い文脈 + 読み取り誤り**: 長さの下限(20 文字)未満の ID(1 件・全条件)。
   ちょうど 20 文字の列・ハイフンを含む 28 文字の列は一部の条件だけで落ちた(読み取りで途中が切れたとみられる)
6. **phone(−11.1pt)— 規則の無い文脈**: 国番号 `+1` の海外の番号(規則は国内表記と `+81` を想定)

下がらなかった細分: email・url_query・card・account・amount・address(和文)・prefixed_token(1 件は読み取り誤り)。
形で決まるものはホールドアウトでも本番並みで、合わせ込みは「手がかり語の一覧」と「人名・会社名の文脈」に集中している。
address は英語の住所 1 件(全条件)だけを落とした(規則の無い文脈)。

## 判断が必要な点(人間の決定事項)

- 手がかり語の一覧(番号・認証情報)をどこまで一般化するか(「〜番号」「〜コード」「〜No.」の形で広げる、表の列の見出しを手がかりにする、など)。
  広げると誤検出が増える可能性がある(ホールドアウトの誤検出は 0 件)
- 手がかりの無い位置の人名(名刺・組織図・一覧)を目標に含めるか。含めるなら辞書の拡充か、配置(役職の直下の大きな文字など)の規則が要る
- ホールドアウトは 2 画面・8 枚と小さい。合わせ込みの確認を続けるなら、規則の調整に使わない画面を別に増やす

## 再現手順

```bash
npm run mask:fixtures:holdout          # 画像と truth.json を生成し自己検査(本番の 28 枚・truth は変えない)
cd src-tauri && . "$HOME/.cargo/env"
MASK_EVAL_SET=holdout MASK_EVAL_LABEL=holdout MASK_EVAL_DATE=2026-10-09 \
  cargo test --lib masking::eval::masking_eval -- --ignored
# → output/reports/masking/eval-2026-10-09-holdout.md と testreport/masking/eval-2026-10-09-holdout.json
```

ホールドアウトでは 95% の判定で止めない(記録だけ)。本番評価(`MASK_EVAL_SET` 未設定)の判定・出力は従来どおり。
