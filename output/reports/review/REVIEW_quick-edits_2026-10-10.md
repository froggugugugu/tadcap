## 指摘

### SHOULD-1: 穴(スポットライト)がすべてトリミング範囲の外にあると、確定で暗さが消え、確定前の見た目と変わる

- **場所**: `src/canvas/crop.ts:71-75`(描画範囲が範囲と重ならない注釈は種類を問わず消す)、`src/canvas/documentSurface.ts:127-128`・`:148`(穴が 0 個なら暗さを塗らない)
- **失敗のシナリオ**:
  1. 1000×800 の画像の左上(50,50)に 100×100 の穴を置く → 穴の外、つまり右下を含む画像のほとんどが 50% 暗くなる
  2. トリミングで右下の (500,400)〜(800,600) を囲む。確定前の表示では、範囲の中は暗いまま見える
  3. Enter で確定すると、穴は範囲の外なので `planCrop()` が消し、穴が 0 個になって暗さが塗られない → 切り抜いた画像は**明るく**なる
- **再現の確認**: `planCrop()` と `spotlightShadeRects()` をそのまま束ねて動かした結果: 「確定前、範囲は暗さで覆われている: true / 確定後の穴の数: 0(消した数 1)」。逆に、穴を消さずに範囲の左上の分だけずらして残すと(画像の外に出る)、`spotlightShadeRects()` は画像全体を 1 つの矩形で塗る = 確定前と同じ見た目になる
- **仕様との関係**: PRD §10 #5「範囲の外へ完全に出た注釈は消す」を穴にもそのまま当てた結果。一方、FR-006 は「切り詰める前と同じ画面上の内容を指す位置」、FR-005 は確定前の表示どおりに切り詰めることを求めている。穴は「穴の外を暗くする」注釈なので、範囲の外にあっても範囲の中の見た目に効いている。仕様の決定がこの組み合わせを想定していたかは文書から読み取れない
- **影響**: 出力の画像が確定前の見た目と違う(⌘Z で戻せる。データの消失ではない)。範囲の中に別の穴が 1 つでも残れば、外の穴を消しても見た目は変わらない(外の穴は範囲の中の暗さに影響しないため)。起きるのは「残る穴が 0 個」のときだけ
- **確信度**: 挙動は高(コードと上記の実行で確認)。仕様に反するかは中(人間の判断が要る)
- **対応案**(人間が選ぶ):
  - A: 現状のまま。ARCH §15 / UI の決定に「穴がすべて範囲外なら暗さも無くなる」と書き足す
  - B: 穴は範囲の外でも消さない(`planCrop()` で `spotlight` だけ常に残してずらす)。見た目は保てるが、画像の外の穴は選べず、50 個の上限に数え続ける
  - C: 残る穴が 0 個になるとき(= 範囲全体が暗かったとき)だけ、範囲の外の穴を 1 つ残す

### CONSIDER-1: 退避の無い履歴の項目を開き直すと、モザイクの粗さの基準が切った後の大きさになる

- **場所**: `src/main.ts:344`(`reloadHistoryItemIntoCanvas` の退避が無いときの `resetDocument()`)、`src/canvas/documentState.ts:122`(`captureSize = surface.size()`)
- **シナリオ**: トリミングした項目の退避が無い状態で開き直すと、`captureSize` が切った後の画像の大きさになり、その後のモザイクのブロックが細かくなる(ADR-002「モザイクの粗さ」の意図から外れる)
- **起きる条件**: 退避は別の画像へ切り替えるたびに作られ、項目が消えるとき(`deleteArchivesOf`)にしか消えない。退避の PNG 化を待つ間に項目が消された場合などに限られ、通常の操作では起きない
- **確信度**: 中(経路はあるが、起きる条件が狭い)
- **対応案**: 不要。気になるなら履歴の項目(`HistoryItem`)に `captureSize` を持たせ、退避が無いときもそれを使う

### CONSIDER-2: 設定ファイルの版を確かめない(SECURITY L-1 と同じ)

- **場所**: `src-tauri/src/settings.rs:53-58`・`:82-88`・`:97-100`
- **シナリオ**: 新しい版が書いた `version: 2` のファイルを `version: 1` で書き戻す。既知のキーの型が違うとファイル全体を壊れたものとして扱い、次の保存でショートカットと未知のキーが消える
- **確信度**: 高(コードから明らか)。今の版の利用では起きない
- **対応案**: 版 2 を入れるタスクで扱う

### CONSIDER-3: 表示中のトリミングの取り消しのメモリに上限が無い(SECURITY L-2 と同じ)

- **場所**: `src/canvas/documentState.ts` `applyCrop()`、`src/canvas/undoStack.ts:25`
- **シナリオ**: 5K の全画面で少しずつ 30 回切ると、取り消し側に最大約 1.7GB の RGBA が残る
- **確信度**: 高。ADR-002 で受容済み
- **対応案**: ARCH §16 の「画面外の canvas のまま持つ」案を、メモリの報告が出たら検討する

## 正確性の確認(問題なし)

| 観点 | 結果 | 根拠 |
| ---- | ---- | ---- |
| トリミングの取り消しの順序 | ✅ | `applyCrop()` は `group[crop, update…, remove…]` を積む。`group` は取り消しで逆順(`commands.ts:135-145`)なので、消した注釈を消した逆順に元の位置へ戻し → 形を戻し → ベースを戻す。`remove` の `index` は「先頭から消した時点の位置」(`crop.ts:73`)で、逆順に差し込むと元の並びに戻る |
| トリミングより前の手 | ✅ | トリミングより前の `pixels` / `flatten` は切る前の座標を持つが、取り消しはスタックの順で `crop` を先に戻すので、戻すときのベースは常に切る前の大きさ |
| 8MB で古い手を捨てる経路 | ✅ | `trimUndoToBudget()` は古い方から連続して捨てる。`crop` が残る限りそれより新しい手は全部残り、`crop` を捨てるときはそれより古い手も既に捨ててある |
| 大きさの変化と範囲・候補 | ✅ | トリミングの範囲は、ツールの変化・自動マスキングの開始・ドキュメントの大きさの変化(`bindCropCancelConditions`)と、画像の差し替え(`main.ts` の `cancelCrop()` 6 か所。同じ大きさの画像への切替も捨てる)で捨てる。自動マスキングの候補は大きさの変化(`bindMaskSessionToDocumentSize`)と画像の差し替えで捨てる |
| 範囲の指定中の ⌘Z | ✅ | 取り消し・やり直しとも範囲をやめるだけ(`undoButton.ts:83-84`、ARCH §15 #4 A) |
| 番号の詰め | ✅ | 番号は `id` の昇順の順位(`stampNumbers()`)を合成ごとに 1 回求める。消すと詰まり、取り消しで `id` ごと戻るので元の番号に戻る。重ね順を変えても変わらない。番号スタンプと穴は 50 個の上限の焼き込みから外れ(`pickBurnTarget()`)、焼き込める注釈が無ければ追加せず通知する(ARCH §15 #2 B・#3 A)。トリミングで範囲外の番号スタンプが消えると残りの番号が詰まるのは ADR-002 の決定どおり |
| 大きさの基準(`styleBasis`) | ✅ | 残る注釈に切る前の対角線を付け、既にあれば変えない。線の太さ・当たり判定・文字の測り直しが同じ基準を使う |
| モザイクの粗さ | ✅ | 手のモザイク・一括モザイクとも `getCaptureSize()`。履歴の退避にも `captureSize` が入る(例外は CONSIDER-1) |
| 縮めてコピー | ✅ | ⌘C・ボタン・撮った直後の自動コピーがすべて `getClipboardPayload()` を通り、`copyRatio(shrinkCopy, 画像の倍率)` で縮める。表示用の canvas は変えない。倍率は履歴の項目にも持ち、開き直しても同じ。トリミングでは変わらない |
| 1 キー切替 | ✅ | 修飾キー・押しっぱなし・IME の変換中(`isComposing`・`keyCode 229`)・入力欄(`isEditableTarget`)・画像なし・ボタンが無効(描画中・自動マスキングの処理中/確認中)で反応しない。設定画面は `<dialog>` が keydown の伝わりを止める(`settingsDialog.ts:304-305`)。E2E `tool-keys.spec.ts` に設定画面・確認中のケースがある |
| 設定の保存 | ✅ | 1 項目だけ変えて保存し、失敗したらメモリの値を戻す。ショートカットの保存でも `shrinkCopy` が消えない(`shortcuts.rs` のテスト) |
| 設定画面の縮めてコピー | ✅ | 保存中・読み込み中はチェックを無効にし、閉じる前に始めた保存が終わってから読み直す(追い越しなし)。失敗したら元の値に戻して文を出す |
| 倍率の読み取り | ✅ | 撮影の `spawn_blocking` の中で読み、読めなくても撮影は成功のまま `None`。取り消された撮影では読まない |
