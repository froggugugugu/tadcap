## 1. 概要

### 1.1 背景・目的

キャプチャ起点の作業（バグ報告、手順書作成、レビュー指摘）を最短操作で完了させる。
「撮る → 矢印・モザイクで印をつける → クリップボードに載せて貼る」をひと続きの最短操作で行える、
ミニマルな OSS ツールを目指す。

- 対象 OS: macOS 14+（macOS 専用。他 OS 対応はしない）
- 主役はキャプチャ、注釈は脇役という位置づけ
- 主要な出力先はクリップボード（チャット・ドキュメントツール・エディタ等へ即貼り付け）

### 1.2 スコープ

MVP は次の 8 機能に限定する: F-01（範囲指定キャプチャ）、F-02（ウィンドウキャプチャ）、
F-04（グローバルショートカット）、F-05（クリップボードへコピー）、F-06a（注釈: 矢印）、
F-07（モザイク）、F-08（メニューバー常駐）、F-09（履歴一覧・セッション内）。

決定ログ（2026-09-23、ゲート1 人間回答）に基づく変更点:
- モザイクを Should → Must に引き上げ（ぼかしは持たない）
- 履歴を Could → Must に引き上げ（編集後画像を保持・再読込）
- F-04（グローバルショートカット）を優先度表記どおり MVP に含める（旧【要確認】7 は解消、§10 参照）
- F-08（メニューバー常駐）を新たに MVP に追加（ショートカットを常時有効にするため常駐が前提となる）
- 枠・テキスト注釈（F-06b）・全画面キャプチャ（F-03）・ファイル保存機能は MVP 外のまま

**【改訂 2026-09-24】決定ログ（人間回答）に基づく追加変更点**:
- F-06b（注釈: 枠・テキスト）を Should → Must に引き上げ、MVP に昇格。矩形枠・円（楕円）枠・テキストの
  3 機能に分割し、それぞれ FR-007・FR-011・FR-012 として定義する（§3 参照）
- 矢印（F-06a・FR-006）の形状を、始点から終点に向かって徐々に太くなるテーパー形状（矢じり付き）に改訂する。
  太さの算出基準（Canvas解像度＝画像の実ピクセルを基準にする考え方）は変更しない
- 新機能 F-10（色の一括指定）・F-11（取り消し／Undo）を新たに MVP へ追加する（FR-013・FR-014、§3 参照）
- F-03（全画面キャプチャ）・ファイル保存機能は引き続き MVP 外のまま

## 2. 用語定義

| 用語 | 定義 |
| ---- | ---- |
| キャプチャ | 画面の一部・ウィンドウを画像として取得する操作。MVP では macOS 標準の `screencapture -i` を利用する |
| 注釈 | キャプチャした画像に Canvas 上で加える書き込み（矢印・モザイク等）の総称 |
| モザイク | 矩形領域をピクセル化して機微情報を隠す加工。決定ログ（2026-09-23）によりモザイクのみを実装し、ぼかしは持たない |
| セッション内履歴 | アプリ起動中に撮影・編集した画像の一覧。アプリ終了で破棄され、永続化しない |
| screencapture CLI | macOS 標準搭載の対話型キャプチャコマンド。MVP のキャプチャ実装方式。`src-tauri/src/capture/` 内で trait 等により差し替え可能な設計にする（§7 参照） |
| ScreenCaptureKit | Apple 提供のキャプチャ用フレームワーク。MVP では採用せず、Phase 4 で NFR-001 の実測値が目標未達の場合に移行を判断する（§7・§11 参照） |
| Canvas | HTML5 `<canvas>`。画像編集（矢印描画・モザイク焼き込み）をすべてここで処理する |

## 3. 機能要件

> FR-ID と要求メモの機能 ID（F-xx）の対応を明記する。MVP 列が「✓」の FR がスコープ内。

### FR-001: 範囲指定キャプチャ（F-01・MVP）
- **概要**: ユーザーが指定した矩形範囲を画面キャプチャする
- **ユーザーストーリー**: ユーザーが、画面の一部だけを、素早く切り取りたい
- **受け入れ基準**:
  - [ ] Rust 側から `screencapture -i <出力パス>` を起動すること
  - [ ] 出力パスは一時ディレクトリ配下にキャプチャごとに一意なファイル名で作成されること（固定パスの上書きをしないこと）
  - [ ] ユーザーが Esc でキャンセルした場合（ファイル未生成）はエラー扱いにせず、何もしないこと
  - [ ] 撮影後、画像がフロントエンドへ渡され Canvas に読み込まれること
- **画面・操作フロー**: キャプチャ開始操作 → OS 標準の範囲選択 UI → 選択完了で Canvas に画像が表示される
- **データモデル変更**: なし（§5 の Capture モデルを参照）
- **実装配置**: `src-tauri/src/capture/` に閉じ込める
- **優先度**: Must

### FR-002: ウィンドウキャプチャ（F-02・MVP）
- **概要**: 特定のウィンドウ単位でキャプチャする
- **ユーザーストーリー**: ユーザーが、背景を含めずに、特定アプリのウィンドウだけをキャプチャしたい
- **受け入れ基準**:
  - [ ] `screencapture -i` 起動中にスペースキーでウィンドウ選択モードへ切り替えられること（OS 標準機能に委譲）
  - [ ] FR-001 と同じ一時ファイル命名規則・キャンセル時の挙動に従うこと
- **画面・操作フロー**: FR-001 と同一の起動 UI からスペースキーでモード切替
- **データモデル変更**: なし
- **優先度**: Must

### FR-003: 全画面キャプチャ（F-03・MVP 外）
- **概要**: 画面全体をキャプチャする
- **ユーザーストーリー**: ユーザーが、画面全体の状態を、そのまま記録したい
- **受け入れ基準**:
  - [ ] （MVP 外のため本 PRD では受け入れ基準を定義しない。後続 PRD で扱う）
- **優先度**: Should（MVP 外）

### FR-004: グローバルショートカット（F-04・MVP）
- **概要**: OS 全体で有効なショートカットキーから、Cmd+Shift+4 のようにどこからでも即座にキャプチャを起動する
- **ユーザーストーリー**: ユーザーが、アプリをアクティブにせずに、キャプチャを即座に開始したい
- **受け入れ基準**:
  - [ ] 他アプリがアクティブな状態でも、既定のショートカットキー押下でキャプチャが起動すること
  - [ ] 既定キーは `Cmd+Shift+4`（OS 予約のため使用不可）を避け、空いている組み合わせとする。候補は `Cmd+Shift+2` とし、実装時に OS 標準ショートカットおよび主要アプリとの衝突を確認したうえで確定すること
  - [ ] ショートカットキーの変更 UI は提供しない（MVP 外）
  - [ ] 押下後、FR-001 と同じ `screencapture -i` が起動すること
  - [ ] 撮影完了後、エディタウィンドウ（メインウィンドウ）が最前面に表示される（フォーカスが移る）こと
  - [ ] Esc でキャンセルした場合は FR-001 と同様エラー扱いにしないこと
- **画面・操作フロー**: グローバルショートカット押下 → OS 標準の範囲選択 UI → 選択完了でエディタウィンドウが前面表示され Canvas に画像が表示される
- **データモデル変更**: なし
- **実装配置**: ショートカット登録は `src-tauri` 側（アプリ初期化処理）で行い、キャプチャ実行は FR-001 の `src-tauri/src/capture/` を再利用する
- **優先度**: Must

### FR-005: クリップボードへコピー（F-05・MVP）
- **概要**: Canvas 上のマークアップ済み最終画像をクリップボードへ直接書き込む
- **ユーザーストーリー**: ユーザーが、編集済みの画像を、他アプリへすぐ貼り付けたい
- **受け入れ基準**:
  - [ ] 目立つ位置に「クリップボードにコピー」ボタンが配置されていること
  - [ ] ショートカット `Cmd + C` でコピーできること
  - [ ] Canvas 上の最終画像（PNG）が macOS のクリップボードへ直接書き込まれること
  - [ ] `@tauri-apps/plugin-clipboard-manager` での書き込みに失敗した場合、Rust コマンドによるフォールバックへ切り替わること
- **画面・操作フロー**: コピー操作 → クリップボードへ書き込み → 成功/失敗のフィードバック表示
- **データモデル変更**: なし
- **優先度**: Must

### FR-006: 注釈: 矢印（F-06a・MVP）【改訂 2026-09-24: テーパー形状化】
- **概要**: 始点から終点へのドラッグで、始点から終点に向かって徐々に太くなるテーパー形状の矢印（矢じり付き）を描画する
- **ユーザーストーリー**: ユーザーが、画像の注目箇所を、方向性のわかりやすい矢印で指し示したい
- **受け入れ基準**:
  - [ ] ドラッグ操作で始点から終点への矢印が Canvas に描画されること
  - [ ] 線の太さは始点側で細く、終点（矢じりの付け根）に向かって徐々に太くなること（線幅が一定のストロークではないこと）
  - [ ] 終点側の太さ・矢じりの大きさは、既存のロジック（Canvas 解像度＝画像の実ピクセルを基準にした決定論的な算出、[MIN_LINE_WIDTH, MAX_LINE_WIDTH] へのクランプ）をそのまま用いること（改訂前の太さ算出基準を変更しない）
  - [ ] 色は FR-013（色の一括指定）で選択中の色を使うこと。既定色は視認性の高い鮮やかなピンク `#FF5C8A` であること
  - [ ] 矢印・矩形・円・テキスト・モザイクの各ツールを共通のツール切替 UI でトグル切り替えできること（FR-007・FR-008・FR-011・FR-012 と共有）
  - [ ] 【改訂 2026-09-24 T31】終点側の太さ（と比率で決まる矢じり・影）を上記算出の 1.5 倍にすること（人間要望「今の 1.5 倍」。比率・上下限をそれぞれ 1.5 倍にする）
  - [ ] 【改訂 2026-09-24 T31】編集中は始点・終点のハンドルで変形、胴体ドラッグで移動できること（下記の共通基準も満たすこと）
  - [ ] 【改訂 2026-09-24 T31】描いた直後の図形は即焼き込まず「編集中」になり、直前に描いた 1 つだけをハンドルでリサイズ・内側ドラッグで移動できること（ハンドルはコピー結果・履歴画像に写らないこと）
  - [ ] 【改訂 2026-09-24 T31】編集中の図形は、次の図形の描き始め・ツール切替・モザイク開始・クリップボードコピー・履歴切替・新規キャプチャ・Enter・図形外のクリックで確定（焼き込み）され、Esc で破棄されること。取り消しは確定済みの操作単位であること
  - [ ] 【改訂 2026-09-24 T32】上記 T31 の「直前の 1 つだけ編集できる」「確定で焼き込む」を次の**オブジェクト共通基準**で置き換える（矢印・矩形・円に共通。FR-007・FR-011 も本基準に従う。テキストは T33 で対象に加える）:
    - [ ] 描いた矢印・矩形・円は画像に焼き込まず「オブジェクト」として保持し、確定後（別の図形を描いた後・ツール切替後・コピー後）でも、クリックで選び直してハンドルでリサイズ・内側（矢印は胴体）ドラッグで移動できること
    - [ ] 選択: クリック位置に重なるオブジェクトのうち最前面（後から描いたもの）を選ぶ。選択中のオブジェクトは内側・ハンドルで掴める。未選択のオブジェクトは線（枠線・矢印の胴体）の付近でのみ掴める（大きな枠の内側に新しい図形を描けるようにするため）。空白のクリックで選択解除、図形ツール選択中の空白ドラッグで新しいオブジェクトを作る（作ったオブジェクトは選択状態になる）
    - [ ] 選択解除: 空白のクリック・Enter・Esc・ツール切替・Canvas 以外のクリック。ドラッグ中の Esc はそのドラッグだけを取り消す（作成中なら何も残さず、移動・リサイズ中なら掴む前に戻す）
    - [ ] 選択ハンドル・枠はコピー結果・履歴画像に写らないこと。コピー・履歴サムネイル・履歴保存は「元画像 + 全オブジェクト」の合成結果であること
    - [ ] 上限: 1 画像あたり 50 個。51 個目を描くと最も古いオブジェクトから元画像へ焼き込み、編集不可にする（描く操作自体は止めない）。この焼き込みは 51 個目の追加と同じ 1 回の取り消しで元に戻る（取り消すと最古のオブジェクトが再び編集可能になる）
    - [ ] 新規キャプチャ時は新しいドキュメント（オブジェクト 0 個）になる。履歴を切り替えて戻ったときの再調整は T34 で対応する（T32 時点の履歴再読込は合成結果の画像を元画像として読み込む）
    - [ ] 【改訂 2026-09-25 T34】選択中のオブジェクトは Delete / Backspace で削除できること（テキスト入力欄にフォーカスがある間は入力欄の文字削除を優先する）。取り消しで元の重ね順に戻ること
    - [ ] 【改訂 2026-09-25 T34】選択中のオブジェクトを「最前面へ」「最背面へ」移動できること（ツールバーのアイコンボタン、⌘⇧F / ⌘⇧B。macOS 標準の Keynote・Pages・フリーボードと同じ割り当て）。ボタンは選択中のみ有効。取り消しできること
    - [ ] 【改訂 2026-09-25 T34】選択中に色見本・カラーピッカー・文字サイズを操作しても選択は外れないこと（色・文字サイズの反映は FR-013・FR-012 参照）
- **画面・操作フロー**: ツール切替でアクティブ化 → ドラッグ → 編集中（ハンドルで変形・移動、【改訂 2026-09-24 T31】）→ 確定（焼き込み）。【改訂 2026-09-24 T32】ドラッグ → オブジェクトとして選択状態 → いつでもクリックで選び直して変形・移動
- **データモデル変更**: なし（Canvas に直接焼き込み、色設定は §5 ToolSettings 参照）
- **優先度**: Must

### FR-007: 注釈: 矩形枠（F-06b・MVP）【改訂 2026-09-24: MVP に昇格】
- **概要**: ドラッグした範囲に矩形（四角形）の枠線を描画し、注目箇所を囲む
- **ユーザーストーリー**: ユーザーが、注目箇所を矩形の枠で囲んで示したい
- **受け入れ基準**:
  - [ ] ドラッグ操作で始点・終点から正規化された矩形が Canvas に描画されること（逆方向ドラッグでも矩形になること）
  - [ ] 塗りつぶしはせず、線（枠線）のみを描画すること
  - [ ] 枠線の太さは Canvas 解像度を基準に決定論的に算出すること（矢印 FR-006 と同じ考え方。矩形のサイズには依存しないこと）
  - [ ] 色は FR-013（色の一括指定）で選択中の色を使うこと
  - [ ] 確定時点で Canvas ピクセルへ焼き込むこと（見た目のみのプレビューで終わらないこと）（【改訂 2026-09-24 T31】確定はポインタを離した時点ではなく下記の確定操作の時点）
  - [ ] 矢印・円・テキスト・モザイクの各ツールと共通のツール切替 UI でトグル切り替えできること
  - [ ] 【改訂 2026-09-24 T31】編集中は四隅のハンドルでリサイズ（Shift で正方形）、内側ドラッグで移動できること（FR-006 の共通基準と同じ確定・破棄操作）
  - [ ] 【改訂 2026-09-24 T31】描いた直後の図形は即焼き込まず「編集中」になり、直前に描いた 1 つだけをハンドルでリサイズ・内側ドラッグで移動できること（ハンドルはコピー結果・履歴画像に写らないこと）
  - [ ] 【改訂 2026-09-24 T31】編集中の図形は、次の図形の描き始め・ツール切替・モザイク開始・クリップボードコピー・履歴切替・新規キャプチャ・Enter・図形外のクリックで確定（焼き込み）され、Esc で破棄されること。取り消しは確定済みの操作単位であること
  - [ ] 【改訂 2026-09-24 T32】確定後も再調整できるオブジェクトとして保持すること（FR-006 のオブジェクト共通基準に従う。未選択の矩形は枠線の付近でのみ掴める）
  - [ ] 【改訂 2026-09-25 v0.2.0後フィードバック】矩形の角は丸める。角の半径は線の太さと矩形の短辺から決定論的に決める（`min(線幅 × 2.5, 短辺 × 0.25)`）。Shift の正方形も同じ。当たり判定・焼き込みも角丸の形に合わせる
- **画面・操作フロー**: ツール切替でアクティブ化 → ドラッグ → 編集中（【改訂 2026-09-24 T31】）→ 矩形確定（焼き込み）。【改訂 2026-09-24 T32】FR-006 と同じくオブジェクトとして保持
- **データモデル変更**: なし

### FR-008: モザイク（F-07・MVP）

### FR-013: 色の一括指定（F-10・MVP）【新設 2026-09-24】
- **概要**: 矢印・矩形・円・テキストの描画に使う色を、プリセット色見本または自由な色から一括で指定する
- **ユーザーストーリー**: ユーザーが、注釈の色を用途（強調・警告等）に応じて選びたい
- **受け入れ基準**:
  - [ ] プリセット色見本(6 色: ピンク `#FF5C8A`(既定)・赤・橙・黄・緑・青。ピンク以外の正確な配色コードは実装フェーズで確定する。§10 決定#11 参照)から選択できること
  - [ ] macOS 標準のカラーピッカー（`<input type="color">` 等）による自由な色指定もできること
  - [ ] 選択した色は、矢印（FR-006）・矩形枠（FR-007）・円枠（FR-011）・テキスト（FR-012）の描画に共通で反映されること
  - [ ] モザイク（FR-008）は色の概念を持たないため、色設定の影響を受けないこと
  - [ ] 色の変更は、変更した時点以降に新しく描く注釈にのみ反映されること。すでに焼き込み済みの注釈の色は変わらないこと
  - [ ] 【改訂 2026-09-25 T34】オブジェクトを選択中に色見本・カラーピッカーで色を選ぶと、そのオブジェクトの色も変わること（取り消しできる 1 操作。カラーピッカーは操作中は見た目だけ変え、確定時に 1 操作にする）。あわせて以後に描く色も変わる。選択していなければ既存の注釈は変わらない（上記どおり）
  - [ ] アプリ起動直後の既定色はピンク `#FF5C8A` であること
- **画面・操作フロー**: ツールバーの色見本または色ピッカーを操作 → 以後の描画に反映
- **データモデル変更**: ToolSettings（§5）を新規定義
- **優先度**: Must

### FR-014: 取り消し(Undo)・やり直し(Redo)(F-11・MVP)【新設 2026-09-24、決定反映 2026-09-24: Redo追加(§10 決定#9)】
- **概要**: 直前の注釈操作（矢印・矩形・円・テキスト・モザイクの焼き込み）を、焼き込み前の状態まで 1 つずつ取り消す。取り消した操作は `Cmd+Shift+Z` で 1 つずつやり直せる(Redo、§10 決定#9)
- **ユーザーストーリー**: ユーザーが、描き間違えた注釈を、撮り直しせずに取り消したい
- **受け入れ基準**:
  - [ ] `Cmd+Z` 押下で、直前の焼き込み操作 1 回分が取り消され、その操作の直前の状態に戻ること
  - [ ] 連続して `Cmd+Z` を押すと、焼き込みの回数分だけ 1 つずつ遡って取り消せること
  - [ ] 取り消し可能な操作がない（キャプチャ直後の状態まで戻っている）場合、`Cmd+Z` は何もしないこと。対応するツールバーのアイコンボタンは無効状態になること
  - [ ] ツールバーに、`Cmd+Z` と同じ操作を行うアイコンボタンを配置すること（既存のキャプチャ・コピー操作と同様、ボタンとショートカットの両方から実行できること）
  - [ ] テキスト入力欄（FR-012）にフォーカスがある間は、`Cmd+Z`・`Cmd+Shift+Z` はテキスト入力欄自体の編集取り消し・やり直しに委ね、Canvas の注釈取り消し・やり直しを実行しないこと
  - [ ] 色・フォントサイズの変更（FR-013）は取り消し・やり直し対象に含まないこと（焼き込みを伴う操作のみが対象）
  - [ ] `Cmd+Shift+Z` 押下で、直前に `Cmd+Z` で取り消した操作を 1 つやり直す(Redo)こと。取り消し(Undo)スタックと対称の Redo スタックを用いること(§10 決定#9、B案採用)
  - [ ] 新しい注釈操作(焼き込み)を行うと Redo スタックはクリアされること(取り消した後に新しく描画した場合、取り消し前の内容へ `Cmd+Shift+Z` で戻ることはできないこと)
  - [ ] やり直し可能な操作がない場合、`Cmd+Shift+Z` は何もしないこと。対応するツールバーのアイコンボタン(取り消しボタンと対称のやり直しボタン)は無効状態になること
  - [ ] 【改訂 2026-09-24 T32】取り消し・やり直しの単位を「操作」にする: オブジェクトの追加・変更（移動 1 回・リサイズ 1 回ごと）・削除（T34）、ベースのピクセル加工（モザイク・テキスト焼き込み）、上限超過による焼き込み（それを引き起こした追加と同じ 1 回）。上限は従来どおり 30 操作（超えた古い操作は取り消せなくなる）。選択・選択解除は取り消し対象に含めない
  - [ ] 【改訂 2026-09-24 T32】T31 の「編集中の図形がある間は `Cmd+Z` が破棄・やり直し無効」は廃止する（編集中という状態が無くなり、描いた直後の図形も通常の追加操作として取り消し・やり直しできる）
  - [ ] 【改訂 2026-09-25 T34】取り消し・やり直しの対象に、削除・色の変更・文字サイズの変更・重ね順の変更を加える。履歴を切り替えて戻った後も、その画像での操作を続きから取り消せる
- **画面・操作フロー**: 注釈を焼き込む → `Cmd+Z`（またはツールバーの取り消しボタン） → 直前の状態に復元。取り消し後に `Cmd+Shift+Z`(またはやり直しボタン) → 取り消した内容が復元される
- **データモデル変更**: UndoStep（§5）を新規定義。Redo スタックも同一の差分方式(変更矩形+焼き込み前ピクセル)を用いる想定。メモリ上限の方針は §11 リスク参照
- **優先度**: Must

## 4. 非機能要件

### NFR-001: キャプチャ起動レスポンス
- **カテゴリ**: パフォーマンス
- **要件**: ショートカット押下（グローバルショートカット FR-004、またはアプリ内キャプチャ開始操作 FR-001/FR-002）から、OS 標準の範囲選択 UI が画面に表示されるまで **200ms 未満**であること
- **計測方法**:
  - 起点: ショートカットの keydown イベント（またはキャプチャ開始ボタンのクリックイベント）を Rust/フロントエンド側でタイムスタンプ記録する
  - 終点: `screencapture -i` プロセスの起動完了（選択カーソルが表示可能になるタイミングの近似として、プロセス起動呼び出しの完了）を記録する
  - 上記 2 点の差分をログ出力し、10 回試行の中央値を基準値とする（自動計測が難しい OS 標準 UI の実際の描画完了は、高速度動画撮影による目視確認で補助的に検証してもよい）
  - Phase 4（モザイク実装後）以降、実測値が目標未達の場合は ScreenCaptureKit への移行を §7・§11 の基準で判断する

### NFR-002: 画面収録権限未許可時の案内
- **カテゴリ**: ユーザビリティ
- **要件**: キャプチャ実行前に、アプリ内で画面収録権限（Screen Recording）の許可状態を事前確認する。未許可の場合は `screencapture -i` を起動せず、案内 UI を表示し「システム設定を開く」ボタンでシステム設定のプライバシーとセキュリティ → 画面収録を開く導線を提供する（権限未許可のままキャプチャすると壁紙のみが写る等、失敗理由がユーザーに分からない問題への対策）
- **計測方法**: 画面収録権限を意図的に未許可にした状態でキャプチャ操作（FR-001/FR-002/FR-004 いずれか）を行い、①`screencapture -i` が起動しないこと、②案内 UI が表示されること、③「システム設定を開く」ボタンで実際にシステム設定アプリの該当画面が開くこと、を手動確認する

### NFR-003: 軽量性
- **カテゴリ**: 保守性
- **要件**: 依存を最小限に保つ（React・Vue 等の重量級フロントエンドフレームワークを使わない、Vanilla HTML/CSS/TypeScript を維持する）
- **計測方法**: 依存パッケージ追加時に §7 の技術スタック方針との整合をレビューで確認する

## 6. 画面・UI仕様

- **パス**: Tauri のシングルウィンドウアプリのため、MVP はメインウィンドウ 1 画面構成（ルーティングなし）。加えてメニューバー常駐（F-08）を持つため、ウィンドウを閉じてもプロセスは終了しない
- **レイアウト**:
  - キャプチャ操作の起点（キャプチャ開始ボタン等）
  - 中央: Canvas 表示領域（撮影した画像を表示・編集）
  - ツール切替 UI: 矢印 / 矩形 / 円 / テキスト / モザイクのトグル（FR-006・FR-007・FR-011・FR-012・FR-008 共通。【改訂 2026-09-24】矩形・円・テキストを追加）
  - 色指定 UI（【新設 2026-09-24】）: プリセット色見本＋カラーピッカーを 1 グループとしてツールバーに配置（FR-013）。既存のアイコン中心・説明文を持たない方針（T19、下記参照）を維持し、色名等のラベルは付けない
  - フォントサイズ指定 UI（【新設 2026-09-24】）: 小・中・大の 3 段階をアイコンボタン群としてツールバーに配置（FR-012・FR-013）。テキストツール専用の設定だが、常時表示し常時操作可能とする（他ツール選択中に変更しても副作用はない）
  - 取り消し（Undo）ボタン（【新設 2026-09-24】）: 既存のキャプチャ・コピーボタンと同様、アイコンボタンとして配置（FR-014）。取り消し不可の状態では無効表示にする
  - 「クリップボードにコピー」ボタンを目立つ位置に配置（FR-005）
  - サイドバー: セッション内履歴リスト（FR-010）。項目クリックで Canvas に再読み込み（編集後画像を表示）
  - メニューバーアイコン（F-09）: 「キャプチャ」「エディタを開く」「終了」の 3 項目メニュー
- **T19方針の維持（【改訂 2026-09-24】新規UI要素にも適用）**: 「主役はキャプチャ画像、UIは脇役」の方針を維持し、新規のツール・色・フォントサイズ・取り消しの各アイコンボタンも説明文を置かずアイコン中心とする。意味は `aria-label`/`title`（ツールチップ）で保持する
- **操作フロー**:
  - 通常操作: キャプチャ開始（アプリ内ボタン / グローバルショートカット / メニューバー）→ OS 標準キャプチャ UI → エディタウィンドウ前面表示・Canvas に画像表示 → ツール切替で注釈/モザイク → クリップボードにコピー → （任意）サイドバーから別の履歴項目を選択して再編集
  - 【新設 2026-09-24】テキスト入力操作: テキストツールを選択 → Canvas クリック → クリック位置にテキスト入力欄が表示される → 文字入力（IME変換対応） → Enter またはフォーカスアウトで確定・焼き込み（Esc でキャンセル）
  - 【新設 2026-09-24】取り消し操作: 注釈を焼き込んだ後に `Cmd+Z`（またはツールバーの取り消しボタン） → 直前の状態に戻る。繰り返し押下で 1 つずつ遡る
  - ウィンドウを閉じた後の操作: メニューバーアイコンから「キャプチャ」（即撮影）または「エディタを開く」（ウィンドウ再表示）
- **ダークモード対応**: ライトテーマ固定（決定ログ 2026-09-23）。OS 設定追従のダークモード対応は MVP 外
- **権限未許可時の画面**: 画面収録権限が未許可の場合、キャプチャを実行せず案内 UI（未許可であることの説明 + 「システム設定を開く」ボタン）を表示する（NFR-002）

### アーキテクチャ影響

- キャプチャ起動（`screencapture -i` の呼び出し、一時ファイル管理、Esc キャンセル判定）は
  `src-tauri/src/capture/` に閉じ込め、フロントエンドから直接シェルコマンドを叩かない
- `src-tauri/src/capture/` 内は、キャプチャ実装（`screencapture -i` 呼び出し）を trait 等の抽象化の背後に置き、
  将来 ScreenCaptureKit 等へ実装を差し替え可能な構造にする（具体的な trait 名・シグネチャは実装フェーズで決定）。
  MVP で実際に有効化する実装は `screencapture -i` のみ
- 画面収録権限の事前確認（NFR-002）は `src-tauri/src/capture/` がキャプチャ実行前に行い、未許可時は `screencapture -i` を起動しない
- グローバルショートカット（FR-004）の登録、メニューバー常駐（FR-009）とウィンドウクローズ時のプロセス継続制御は、
  アプリ初期化処理として `src-tauri` 側が担う。どちらもキャプチャ実行は `src-tauri/src/capture/` を共通利用する
- クリップボード書き込みは `@tauri-apps/plugin-clipboard-manager` を第一手段とし、失敗時のみ Rust コマンドへフォールバックする経路を用意する
- Canvas 上の注釈・モザイク処理（矢印描画、ピクセル化）はフロントエンド（TypeScript）側の責務とし、Rust 側は関与しない
- 履歴（HistoryItem）はフロントエンドのメモリ上でのみ保持し、永続化層を持たない（§5）

### 参考: ScreenCaptureKit との比較（将来移行判断のための材料）

MVP は `screencapture -i` CLI を採用する（決定ログ 2026-09-23）。Phase 4 で NFR-001 の実測値が
目標（200ms 未満）未達の場合、以下を踏まえて ScreenCaptureKit への移行を判断する。

| 観点 | `screencapture -i`（MVP 採用） | ScreenCaptureKit（将来候補） |
| ---- | ------------------------------ | ----------------------------- |
| 選択 UI | OS 標準の範囲選択 UI をそのまま利用できる | 自前で範囲/ウィンドウ選択 UI を実装する必要がある |
| 依存 | 追加依存なし（OS 標準コマンドを呼び出すのみ） | Apple フレームワークへの依存が増える（バインディング・権限設計の複雑化） |
| データ受け渡し | 一時ファイル経由（ディスク I/O が発生） | メモリ上でフレームを直接受け取れる（ディスク I/O 不要、高速化が見込める） |
| 自アプリの除外 | 制御不可（自アプリのウィンドウも選択対象になり得る） | キャプチャ対象から自アプリを除外できる |
| 実装コスト | 低い（CLI 呼び出しのみ） | 高い（選択 UI・権限フロー・フレーム処理を自前実装） |

### 依存方向

`project-config.md` §4（アーキテクチャ）が未記入のため、プロジェクト全体の依存方向ルールは本 PRD の時点では確定していない。
本 PRD が前提とする最小限の分離は以下の通り。

- フロントエンド（Canvas / UI）→ Rust コマンド呼び出し: 可（Tauri の `invoke` 経由）
- Rust 側 → フロントエンド固有ロジックへの依存: 禁止
- システムコマンド実行（`screencapture` 等）はフロントエンドから直接行わない
