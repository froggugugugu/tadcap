# PRD: 小さな編集機能(番号・記号スタンプ / トリミング / スポットライト / 縮めてコピー / ツールの 1 キー切替)

> 生成元: `output/brainstorm/BRAINSTORM_quick-edits_2026-10-10.md`
> 生成日: 2026-10-10
> ステータス: Approved(2026-10-10 ゲート 1 通過。§10 の要確認 11 件は人間が決定済み)
> 関連: `output/prd/PRD_tadcap_mvp.md`(既存機能)・`output/prd/PRD_auto-masking.md`(自動マスキング)。本書の FR 番号は本書内だけで通用する。既存 PRD の FR を指すときは「MVP FR-006」「自動マスキング FR-012」のように書く

## 1. 概要

### 1.1 背景・目的

手順や指摘を伝える画像を、**他のアプリを使わずに Tadcap だけで**作って貼れるようにする。そのために次の 4 つと、ツールの 1 キー切替を足す。

- 番号・記号のスタンプ(手順の順番、良い/悪いの印)
- 撮った後の切り抜き(トリミング)
- 見るべき所以外を暗くする強調(スポットライト)
- 貼り先で大きすぎないようにする縮小(縮めてコピー)

既存の方針「撮る → 描き込む → 貼るを最短で」「何も残さない」(MVP PRD §1.1、セッション内だけの履歴)を崩さない。

- 成功条件: 番号付きの手順画像を、Tadcap だけで作って貼れる(他のアプリを使わない)。実機の操作で確かめる(NFR-001)
- 後続: 「手順書モード」は番号スタンプを土台に、本 PRD の承認後に別ブレストで扱う

### 1.2 スコープ

#### スコープ内

- 番号スタンプ: 選択中の色の丸に白い数字。クリックするたびに連番(画像ごとに 1 から)。消すと以降の番号を詰める。後から移動・削除できる。大きさは既存の文字サイズ(小・中・大)に連動
- 記号スタンプ: 番号スタンプと同じ仕組みで、数字の代わりに記号(種類は §10 #1)を置く
- トリミング: 矩形の範囲を囲み、外側を暗く表示 → Enter / ボタンで確定、Esc でやめる。⌘Z で戻せる。描いた注釈は残して位置を合わせ、範囲外にはみ出した部分は切れる
- スポットライト: 囲んだ範囲(穴)以外を暗くする。複数の穴を開けられる。後から移動・リサイズ・削除できる。暗さは固定(中くらい)
- 縮めてコピー: 設定画面で「コピーを等倍に縮める」をオンにできる(倍率 2 倍の画面で撮った画像は 1/2)。⌘C・コピーボタン・撮った直後の自動コピーに同じく効く
- ツールの 1 キー切替: 既存ツール(矢印・矩形・円・テキスト・モザイク)と新しいツール(スタンプ・スポットライト・トリミング)を、修飾キーなしの 1 文字で切り替える

#### スコープ外

- 回転・反転
- 矩形以外の切り抜き(自由な形・楕円など)、縦横比の固定、数値での範囲指定
- ファイルへの保存、画質・形式の細かい設定、縮小後の最大幅の指定(縮めてコピーは等倍のオン/オフのみ)
- 利用者による記号の追加
- スポットライトの暗さ・ぼかしの選択(暗さは固定 1 種)
- ツールのキー割り当ての変更
- 番号の手入力・付け替え(番号は置いた順で自動的に決まる)
- 手順書モード(別ブレスト)

## 2. 用語定義

| 用語 | 定義 |
| ---- | ---- |
| スタンプ | クリック 1 回で置く、丸の中に数字または記号を描いた注釈。番号スタンプと記号スタンプの総称 |
| 番号スタンプ | 数字を描いたスタンプ。数字は画像内で置いた順に 1 から自動で決まる(FR-002) |
| 記号スタンプ | 数字の代わりに決まった記号を描いたスタンプ。番号の連番には数えない |
| 連番 | 1 つの画像の中の番号スタンプに、置いた順で 1, 2, 3… と振る番号 |
| トリミング | 表示中の画像を矩形の範囲に切り詰める操作。ベースの大きさが変わる |
| トリミング範囲 | トリミングで残す矩形。確定前は範囲の外側を暗く表示する |
| スポットライト | 画像のうち、穴の外側を固定の暗さで暗くする注釈 |
| 穴 | スポットライトで暗くしない矩形の範囲。1 つの画像に複数置ける。穴の 1 つ 1 つが注釈(オブジェクト)である |
| 縮めてコピー | コピー時に、画像を撮った画面の倍率で割った大きさ(等倍)に縮めてクリップボードへ入れる設定 |
| 画面の倍率 | 撮った画面の、画面上の 1 点あたりの実ピクセル数。高精細な画面では 2、そうでない画面では 1 |
| 1 キー切替 | 修飾キー(⌘・⇧・⌥・⌃)を押さずに 1 文字のキーでツールを切り替える操作 |
| オブジェクト | 既存の用語(MVP FR-006 オブジェクト共通基準)。画像に焼き込まず、後から選び直して調整できる注釈。1 画像 50 個まで(`OBJECT_LIMIT`、`src/canvas/objectModel.ts:16`) |
| ベース | 既存の用語。表示中画像の元画像部分(`src/canvas/documentState.ts`)。モザイク・上限超過の焼き込みはここに適用する |

## 3. 機能要件

### FR-001: 番号スタンプを置く

- **概要**: スタンプツールで画像をクリックすると、その位置に番号スタンプが置かれる
- **ユーザーストーリー**: 手順を伝える人が、画面のどこを何番目に操作するかを、クリックだけで示したい
- **受け入れ基準**:
  - [ ] スタンプツール(種類: 番号)を選んで画像をクリックすると、クリック位置を中心に番号スタンプが 1 つ置かれること
  - [ ] 番号スタンプは、選択中の色(MVP FR-013)で塗った丸に、白い数字を描いたものであること
  - [ ] 2 桁の数字(10 以上)も丸からはみ出さずに読めること
  - [ ] 大きさは選択中の文字サイズ(小・中・大、MVP FR-012)に連動し、実寸は画像の解像度から決定論的に算出すること(テキストと同じ考え方。新しい大きさの設定は増やさない)
  - [ ] 置いたスタンプは選択状態になること(既存のオブジェクトと同じ)
  - [ ] スタンプツール選択中に既存のスタンプをクリックした場合は、新しいスタンプを置かずにそのスタンプを選ぶこと(ドラッグで移動できる)
  - [ ] 置く操作は取り消し(⌘Z)の 1 手であること
- **画面・操作フロー**: スタンプツール選択 → 画像をクリック → スタンプが置かれ選択状態 → 続けてクリックで次の番号
- **データモデル変更**: オブジェクトの種類にスタンプを追加(§5)
- **優先度**: Must

### FR-002: 連番の維持

- **概要**: 番号スタンプの数字は、画像ごとに置いた順で 1 から振る。消すと以降を詰める
- **ユーザーストーリー**: 手順を伝える人が、途中のスタンプを消しても番号を手で直さずに済ませたい
- **受け入れ基準**:
  - [ ] 新しい画像(新規キャプチャ)では、最初に置いた番号スタンプが 1 になること
  - [ ] 番号スタンプの数字は、その画像の番号スタンプを**置いた順**に 1, 2, 3… であること(移動・重ね順の変更では数字が変わらないこと)
  - [ ] 番号スタンプを 1 つ消すと、それより後に置いた番号スタンプの数字が 1 ずつ詰まること(例: 1・2・3 から 2 を消すと、残りは 1・2)
  - [ ] 消した操作を取り消すと、消す前の数字の並びに戻ること
  - [ ] 記号スタンプは連番に数えないこと
  - [ ] 履歴を切り替えて戻った画像では、その画像の続きの番号から置けること
  - [ ] 50 個の上限で番号スタンプがベースへ焼き込まれた場合の数字の扱いは §10 #9 の決定に従うこと
- **画面・操作フロー**: FR-001・FR-003 の結果として数字が自動で決まる
- **データモデル変更**: 数字そのものは持たず、置いた順から求める想定(§5【仮定】)
- **優先度**: Must

### FR-003: スタンプの調整

- **概要**: 置いたスタンプを、既存のオブジェクトと同じく後から選び直して調整できる
- **ユーザーストーリー**: 手順を伝える人が、置く位置を間違えたスタンプを撮り直さずに直したい
- **受け入れ基準**:
  - [ ] スタンプをクリックで選び、ドラッグで移動できること(MVP FR-006 のオブジェクト共通基準に従う)
  - [ ] 選択中のスタンプを Delete / Backspace で消せること
  - [ ] 選択中のスタンプに色見本・カラーピッカーで色を選ぶと、そのスタンプの色が変わること(テキスト・図形と同じ。MVP FR-013 T34)
  - [ ] 選択中のスタンプに文字サイズ(小・中・大)を選ぶと、そのスタンプの大きさが変わること(中心の位置は保つ)
  - [ ] スタンプにはリサイズのハンドルを出さないこと(大きさは文字サイズだけで決まる)
  - [ ] 重ね順の変更(⌘⇧F / ⌘⇧B)ができること
  - [ ] 移動・削除・色・大きさ・重ね順の変更が、それぞれ取り消しの 1 手であること
  - [ ] 選択の枠は、コピー結果・履歴画像に写らないこと
- **画面・操作フロー**: クリックで選択 → ドラッグ / Delete / 色・文字サイズ・重ね順の操作
- **データモデル変更**: なし(FR-001 の種類を既存のオブジェクトの仕組みで扱う)
- **優先度**: Must

### FR-004: 記号スタンプ

- **概要**: 番号スタンプと同じ仕組みで、決まった記号のスタンプを置く
- **ユーザーストーリー**: 指摘を伝える人が、良い所・悪い所・注意点を印 1 つで示したい
- **受け入れ基準**:
  - [ ] スタンプの種類として、番号と記号(種類は §10 #1)を切り替えられること
  - [ ] 記号スタンプの置き方・見た目の大きさ・調整(FR-001・FR-003)は番号スタンプと同じであること
  - [ ] 記号スタンプの色は §10 #2 の決定に従うこと
  - [ ] スタンプの種類の切り替えは、取り消しの対象に含めないこと(色・文字サイズの選択と同じ「これから置くものの設定」)
- **画面・操作フロー**: スタンプの種類を選ぶ → クリックで置く。ツールの構成(1 ツール + 種類の切替 / 別ツール)は §10 #3
- **データモデル変更**: スタンプの種類を持つ(§5)
- **優先度**: Must

### FR-005: トリミングの範囲指定と確定・中止

- **概要**: トリミングツールで矩形の範囲を囲み、確定すると画像がその範囲に切り詰められる
- **ユーザーストーリー**: 利用者が、撮った後で余計な所を切り落とし、撮り直さずに必要な範囲だけを貼りたい
- **受け入れ基準**:
  - [ ] トリミングツールを選んで画像上をドラッグすると、トリミング範囲の矩形が表示され、範囲の外側が暗く表示されること
  - [ ] 確定前は、ハンドルで範囲をリサイズ・内側のドラッグで移動できること
  - [ ] Enter または確定ボタンで確定すると、画像がトリミング範囲の大きさに切り詰められること
  - [ ] Esc またはやめるボタンで、画像を変えずにトリミングをやめられること
  - [ ] 範囲は画像の内側に収まること(はみ出すドラッグは画像の端で止める)
  - [ ] 範囲の座標は画像の実ピクセルに揃えること(端数を持たない。丸めは設計で決め、決定論的であること)
  - [ ] 範囲が画像全体と同じ、または幅・高さが 0 のときは、確定しても画像が変わらず、取り消しの手も積まないこと
  - [ ] 確定前の暗い表示・範囲の枠・ハンドルは、コピー結果・履歴画像に写らないこと(確定前に ⌘C した場合は、トリミングしていない画像がコピーされる)
  - [ ] 確定は取り消し(⌘Z)の 1 手であり、1 回の取り消しで切り詰める前の画像と注釈の位置に戻ること。やり直し(⇧⌘Z)で再び切り詰められること
  - [ ] 【仮定】確定前に他のツールへ切り替えた・新規キャプチャ・履歴の切替をしたときは、トリミングをやめる(画像を変えない)
- **画面・操作フロー**: トリミングツール選択 → ドラッグで範囲 → (ハンドルで調整)→ Enter / 確定ボタン で切り詰め、Esc / やめるボタン で中止
- **データモデル変更**: 切り詰めを 1 手とする取り消しのコマンド(§5)
- **優先度**: Must

### FR-006: トリミングと注釈の位置合わせ

- **概要**: トリミングの確定時に、オブジェクト(矢印・矩形・円・テキスト・スタンプ・穴)を残し、切り詰めた画像上で同じ見た目の位置に来るよう座標をずらす
- **ユーザーストーリー**: 利用者が、描いた後で切り抜いても、描き直さずに済ませたい
- **受け入れ基準**:
  - [ ] 確定後、各オブジェクトが、切り詰める前と同じ画面上の内容を指す位置にあること(座標がトリミング範囲の左上の分だけずれること)
  - [ ] 範囲の外へ一部はみ出したオブジェクトは残り、はみ出した部分はコピー結果・表示で切れること
  - [ ] 範囲の外へ完全に出たオブジェクトの扱いは §10 #5 の決定に従うこと
  - [ ] 確定後も、残ったオブジェクトを選び直して移動・調整できること
  - [ ] 大きさが画像の解像度から決まるもの(矢印の太さ・枠の線幅・文字・スタンプの大きさ)は、トリミングの前後で見た目の大きさが変わらないこと【仮定】(画像が小さくなっても太さを再計算しない)
  - [ ] ベースに焼き込まれたもの(モザイク・上限超過で焼き込まれたオブジェクト)は、ベースと一緒に切り詰められること
- **画面・操作フロー**: FR-005 の確定と同時に行う
- **データモデル変更**: なし(既存のオブジェクトの座標を書き換える)
- **優先度**: Must

### FR-007: トリミングと他の機能

- **概要**: トリミングで画像の大きさが変わっても、取り消し・履歴・自動マスキング・縮めてコピーが正しく動く
- **ユーザーストーリー**: 開発者が、座標を持つすべての機能がトリミング後も壊れないことを保証したい
- **受け入れ基準**:
  - [ ] トリミングより前に行った操作(モザイク・注釈の追加など)も、トリミングを取り消した後に続けて取り消せること(取り消しの順序どおり)
  - [ ] コピー成功時に更新される履歴の画像・サムネイル(MVP FR-010)が、切り詰め後の画像になること
  - [ ] 履歴を切り替えて戻った後も、トリミング後の画像で続きの操作・取り消しができること(取り消しの退避の上限 `ARCHIVED_UNDO_BYTES_LIMIT` を超える分は、既存どおり取り消せなくなってよい)
  - [ ] 自動マスキングの処理中・確認中(自動マスキング FR-012 の確認モード)は、トリミングを始められないこと
  - [ ] トリミングの確定で画像が変わったとき、自動マスキングの候補が残っていれば破棄すること
  - [ ] 縮めてコピー(FR-011)は、切り詰め後の画像に対して同じ倍率で効くこと
- **画面・操作フロー**: —
- **データモデル変更**: なし
- **優先度**: Must

### FR-008: スポットライトの穴を開ける

- **概要**: スポットライトツールで矩形をドラッグすると、その範囲を穴として残し、画像の穴の外側が暗くなる
- **ユーザーストーリー**: 指摘を伝える人が、受け取る人に見るべき所を一目で分からせたい
- **受け入れ基準**:
  - [ ] スポットライトツールを選んで画像上をドラッグすると、その矩形が穴になり、穴の外側が暗く表示されること
  - [ ] 続けてドラッグすると穴を追加でき、複数の穴のどれの内側も暗くならないこと(穴が重なっても、重なった所が暗くならないこと)
  - [ ] 暗さは固定の 1 種類で、周りの文字がうっすら読める程度であること(値は設計で 1 つに決め、明るい画面・暗い画面のキャプチャの両方で実機確認する)
  - [ ] 暗さは何個穴を開けても 1 段階であること(穴ごとに暗さが重ならないこと)
  - [ ] 暗さがかかる対象(ベースだけか、他の注釈も含むか)は §10 #7 の決定に従うこと
  - [ ] 穴の形は §10 #6 の決定に従うこと
  - [ ] スポットライトは選択中の色の影響を受けないこと(モザイクと同じく色を持たない)
  - [ ] 穴を開ける操作は取り消しの 1 手であること
- **画面・操作フロー**: スポットライトツール選択 → ドラッグで穴 → 選択状態 → 続けてドラッグで次の穴
- **データモデル変更**: オブジェクトの種類に穴を追加(§5)
- **優先度**: Must

### FR-009: スポットライトの穴の調整

- **概要**: 開けた穴を、既存の矩形と同じく後から選び直して移動・リサイズ・削除できる
- **ユーザーストーリー**: 指摘を伝える人が、穴の位置・大きさを撮り直さずに合わせたい
- **受け入れ基準**:
  - [ ] 穴をクリックで選び、ハンドルでリサイズ・内側のドラッグで移動できること(MVP FR-006 のオブジェクト共通基準に従う)
  - [ ] 選択中の穴を Delete / Backspace で消せること。最後の穴を消すと、画像全体が暗くない状態に戻ること
  - [ ] 移動・リサイズ中も、暗い表示が穴の位置に追従すること
  - [ ] 移動・リサイズ・削除がそれぞれ取り消しの 1 手であること
  - [ ] 穴は 1 画像 50 個の上限(MVP FR-006)に数えること。上限超過で最も古いオブジェクトが穴だった場合の扱いは §10 #8 の決定に従うこと
- **画面・操作フロー**: クリックで選択 → ハンドル / ドラッグ / Delete
- **データモデル変更**: なし(FR-008 の種類を既存のオブジェクトの仕組みで扱う)
- **優先度**: Must

### FR-010: スポットライトの出力

- **概要**: スポットライトの暗さは、コピー結果に焼き込まれる(貼った先でも暗いまま)
- **ユーザーストーリー**: 受け取る人が、貼られた画像だけで見るべき所が分かるようにしたい
- **受け入れ基準**:
  - [ ] ⌘C・コピーボタン・撮った直後の自動コピーの結果に、スポットライトの暗さが写ること
  - [ ] 履歴のサムネイル・履歴画像にも暗さが写ること(既存の「元画像 + 全オブジェクト」の合成と同じ)
  - [ ] 穴の選択の枠・ハンドルはコピー結果に写らないこと
  - [ ] 自動マスキングの文字の読み取りは、スポットライトの影響を受けずにベースを読むこと(自動マスキング FR-002)
- **画面・操作フロー**: —
- **データモデル変更**: なし
- **優先度**: Must

### FR-011: 縮めてコピーの設定

- **概要**: 設定画面に「コピーを等倍に縮める」のオン/オフを置く
- **ユーザーストーリー**: 利用者が、高精細な画面で撮った画像を、貼った先で大きすぎない大きさで貼りたい。普段の操作は増やしたくない
- **受け入れ基準**:
  - [ ] 設定画面(既存の `<dialog>`、`src/ui/settingsDialog.ts`)で、縮めてコピーをオン/オフできること
  - [ ] 既定はオフであること(今の動作のまま)
  - [ ] 設定はアプリを再起動しても保たれること(既存の設定ファイル `settings.json` に保存)
  - [ ] 設定の項目がない古い設定ファイルを読んだとき、オフとして動くこと
  - [ ] 設定の切り替えは、切り替えた後のコピーから効くこと
- **画面・操作フロー**: メニュー(トレイ / アプリメニュー)から設定画面を開く → チェックを切り替える(保存ボタンは置かない。既存の設定画面と同じ)
- **データモデル変更**: 設定に 1 項目追加(§5)
- **優先度**: Must

### FR-012: 縮めてコピーの適用

- **概要**: 設定がオンのとき、コピーする画像を、撮った画面の倍率で割った大きさに縮める
- **ユーザーストーリー**: 利用者が、どの経路でコピーしても同じ大きさで貼れるようにしたい
- **受け入れ基準**:
  - [ ] 設定がオンのとき、⌘C・コピーボタン・撮った直後の自動コピーのすべてで、縮めた画像がクリップボードへ入ること
  - [ ] 縮めた画像の幅・高さは、元の幅・高さを画面の倍率で割り、四捨五入した値(最小 1px)であること
  - [ ] 画面の倍率が 1 の画像、または倍率が分からない画像は、縮めずにそのままコピーすること
  - [ ] 画面の倍率をどこから決めるかは §10 #10 の決定に従うこと
  - [ ] 縮めるのはクリップボードへ入れる画像だけで、エディタの表示・編集・履歴の画像は元の解像度のままであること
  - [ ] 縮めた画像でも、モザイクの部分は元の文字が読めない状態のままであること(実機確認)
  - [ ] 設定がオフのときは、今と同じ画像(元の解像度)がコピーされること
- **画面・操作フロー**: 普段の操作は変わらない(コピーの結果の大きさだけが変わる)
- **データモデル変更**: 画像ごとに画面の倍率をメモリ上で持つ(§5)
- **優先度**: Must

### FR-013: ツールの 1 キー切替

- **概要**: すべてのツールを、修飾キーなしの 1 文字で切り替える
- **ユーザーストーリー**: 利用者が、ツールバーへマウスを動かさずにツールを持ち替え、手順画像を速く作りたい
- **受け入れ基準**:
  - [ ] 矢印・矩形・円・テキスト・モザイク・スタンプ・スポットライト・トリミングの各ツールに、修飾キーなしの 1 文字を割り当てること(割り当ては §10 #4)
  - [ ] キーを押すと、ツールバーのボタンを押したのと同じ結果になること(選択中のツールのキーをもう一度押すと選択が外れる。既存のトグルと同じ)
  - [ ] ⌘・⇧・⌥・⌃ のいずれかを押しながらのときは反応しないこと(⌘C・⌘Z・⇧⌘Z・⌘⇧F・⌘⇧B・⌘⇧M などの既存のショートカットを奪わないこと)
  - [ ] テキストの入力中・IME の変換中・設定画面を開いている間(キーの記録中を含む)は反応しないこと
  - [ ] 自動マスキングの処理中・確認中は反応しないこと(ツールボタンが無効なのと同じ。自動マスキング FR-012)
  - [ ] 画像を表示していないときは、ツールボタンと同じ扱いであること(ボタンが押せない状態ならキーも反応しない)
  - [ ] 日本語入力がオンの状態でも、同じキーで切り替わること(キーの判定は文字ではなく物理キーで行う)
  - [ ] ツールボタンのツールチップに、割り当てたキーが表示されること
- **画面・操作フロー**: キー押下 → ツールが切り替わる
- **データモデル変更**: なし
- **優先度**: Must

## 5. データモデル

### 新規スキーマ

すべてメモリ上のモデル(永続化しない)。設定の 1 項目だけを例外として保存する。

| モデル | フィールド | 内容 |
| ------ | ---------- | ---- |
| スタンプ(オブジェクトの新しい種類) | 中心の位置・種類(番号 / 記号の各種)・色・文字サイズの段階 | 数字は持たず、置いた順から求める【仮定】 |
| 穴(オブジェクトの新しい種類) | 矩形(画像のピクセル座標) | 暗さは定数で、穴ごとには持たない |
| スタンプの種類の選択 | 番号 / 記号の各種 | これから置くスタンプの種類。色・文字サイズと同じく取り消しの対象外。永続化しない |
| 画面の倍率 | 画像ごとの数値(1 または 2。分からないときは 1) | 縮めてコピーで使う。履歴の項目ごとに持つ |

- 「置いた順」を数字の根拠にするため、置いた順を重ね順とは別に持つ必要がある(重ね順の変更 ⌘⇧F / ⌘⇧B で数字を変えないため)。持ち方は設計で決める
- 座標は既存のツールと同じく画像の実ピクセル基準とする(`src/canvas/coords.ts` の `Rect`)

| -------- | ---------- | -------- | ---------- |

## 7. 技術的考慮事項

### 7.1 アーキテクチャへの影響

- スタンプ・穴は、既存のオブジェクト(`src/canvas/objectModel.ts`・`shapeEdit.ts`・`documentState.ts`)の新しい種類として足す。選択・移動・削除・重ね順・取り消し・上限・履歴への退避は既存の仕組みに乗る
- スポットライトの暗さは、オブジェクト 1 つずつの描画ではなく「全部の穴の和の外側を 1 回だけ暗くする」描画になる。合成(表示・コピー・履歴)の順番に、暗さを描く段を 1 つ足す必要がある(§10 #7 の決定で位置が変わる)
- トリミングは、ベースの大きさが変わる初めての操作になる。今の取り消しのピクセル差分(`pixels` / `flatten`)は画像の大きさが変わらない前提のため、山場はここにある。Canvas の大きさ・表示の倍率(`src/canvas/coords.ts`)・自動マスキングの候補の座標・履歴の画像の更新に影響する
- 縮めてコピーは、クリップボードへ渡す直前(`src/canvas/documentSurface.ts` の PNG 書き出し)で縮める。撮った直後の自動コピー(`copyAfterCapture`、`src/ui/clipboardButton.ts`)も同じ経路を通る
- 1 キー切替は、既存のキー判定の作法(`src/ui/shortcutGuards.ts` の `isEditableTarget()`、`shortcutFormat.ts` の `event.code` による判定)に合わせ、判定を純粋関数にしてユニットテストする

### 7.2 技術選定の選択肢(決定は `/architecture`)

| 論点 | A 案 | B 案 | 判断材料 |
| ---- | ---- | ---- | -------- |
| トリミングの取り消し | 切り詰める前のベース全体とオブジェクト全体を退避する新しいコマンド | ベースの差し替え + 各オブジェクトの `update` + 範囲外の `remove` を `group` にまとめる | A: 単純だが退避のバイト数が大きい / B: 既存の種類を再利用できるが、ベースの大きさの変更は新しい種類が要る |
| 画面の倍率の取得(§10 #10) | 撮った画像の PNG に書かれた解像度の情報から求める(Rust 側で読む) | 撮った時点の画面の倍率を OS から取る | A: 画像だけで決まり、複数の画面が混在しても撮った画面に合う / B: 範囲が複数の画面にまたがるときの基準が曖昧 |
| 縮める処理の場所 | webview の Canvas で縮めて PNG 化 | Rust 側で縮める | A: 既存の書き出しの経路のまま / B: 縮める品質を細かく選べるが、依存の追加が要る可能性(NFR-003) |

- 【前提】依存パッケージは追加しない(ブレスト §2)。上記はいずれも既存の Canvas と標準ライブラリの範囲で検討する

### 7.3 依存方向

- 既存の層: `ui/` → `canvas/` → `ipc/`。スタンプ・穴・トリミングのモデルと純粋関数は `canvas/` に置き、`ui/` から使う。`canvas/` から `ui/` への依存は作らない
- 1 キー切替の判定は `ui/`(既存の `selectionKeys.ts`・`arrangeButtons.ts` と同じ層)に置く
- 縮めてコピーの設定は `ipc/settings` 経由で読み、Rust 側は `settings.rs` に項目を足すだけにする
- 依存方向の検出コマンドは未導入(project-config.md §3)のため、レビューで確認する

### 7.4 既存の数値との整合

- オブジェクトの上限は 1 画像 50 個(`OBJECT_LIMIT`)、取り消しは 30 手(`UNDO_STACK_LIMIT`、`src/canvas/undoStack.ts`)のまま変えない
- 文字の大きさは画像の対角線などから求める既存の比率(`src/canvas/tools/textLayout.ts` の `FONT_SIZE_RATIO`)があり、スタンプの大きさも同じ考え方で決める(具体的な比率は設計で決める)

## 8. テスト戦略

### 8.1 ユニットテスト(Vitest / cargo test)

- 連番: 置いた順の数え方、途中を消したときの詰め、取り消しで戻る、記号を数えない、重ね順を変えても数字が変わらない、上限で焼き込まれたとき(§10 #9)
- スタンプの大きさ: 文字サイズの段階 × 画像の解像度の算出(決定論的であること)、2 桁の収まり
- 穴: 複数の穴の和の外側の領域、重なり、暗さが 1 段階であること、最後の穴を消した状態
- トリミング: 範囲のクリップと整数化、全体と同じ・大きさ 0 で何もしないこと、オブジェクトの座標のずらし、範囲外のオブジェクトの扱い(§10 #5)、取り消し・やり直しで元に戻ること、トリミングより前の操作を続けて取り消せること
- 縮めてコピー: 倍率ごとの縮めた大きさ(四捨五入・最小 1px)、倍率 1・不明で縮めないこと、設定オフで縮めないこと
- 1 キー切替: キーとツールの対応、修飾キー付き・入力中・IME 変換中・自動マスキングの確認中で反応しないこと
- 設定(cargo test): 項目がない設定ファイルをオフとして読む、オフのときはキーを書かない

### 8.2 E2E テスト(Playwright、既存の IPC モック方式)

- 番号スタンプを 3 つ置く → 2 番目を消す → 番号が詰まる → ⌘Z で戻る
- トリミング: 範囲を囲む → Esc で中止 / Enter で確定 → 注釈の位置が合っている → ⌘Z で戻る
- スポットライト: 穴を 2 つ → 移動・削除 → コピー結果に暗さが写る(コピーされる画像の検証)
- 縮めてコピー: 設定オン/オフで、コピーされる画像の大きさが変わる(倍率はモックで与える)
- 1 キー切替: 各キーでツールが切り替わる、テキスト入力中は文字が入る
- 見た目の確認は既存の `e2e/screenshots/*.visual.ts` の作法でスタンプ・穴・トリミング範囲を追加

### 8.3 手動確認(実機)

- NFR-001 の一連の操作(成功条件)
- スポットライトの暗さの見え方(明るい画面・暗い画面のキャプチャ)
- 縮めてコピーで、倍率 2 倍の画面・倍率 1 の画面・両方を接続した状態のそれぞれで撮った画像の大きさと、モザイクの読めなさ
- ドラッグ中の表示の追従(NFR-004)

## 11. リスク・懸念事項

| リスク | 影響度 | 対策 |
| ------ | ------ | ---- |
| トリミングで画像の大きさが変わり、座標を持つ機能(注釈・取り消し・履歴・自動マスキング・表示の倍率)が壊れる | 高 | Phase 5 として最後に置き、全オブジェクトの種類がそろってから行う。取り消しの順序・履歴の切替を含むユニット・E2E を先に書く(§8) |
| トリミングの取り消しで切り詰める前のベース全体を退避し、メモリを使う(5K 相当で数十 MB) | 中 | 取り消しは 30 手の上限内。履歴へ退避するときは既存の上限 8MB で古い手から捨てる(FR-007)。設計で退避の量を見積もる |
| ツールが 8 つになり、ツールバーが混む・どのツールか迷う | 中 | スタンプを 1 ツールにまとめる(§10 #3)、1 キー切替とツールチップのキー表示(FR-013)、並びは UI 設計で決める |
| スポットライトで周りが読めず、受け取る人が文脈を失う | 中 | 暗さを「うっすら読める」中くらいに固定し、実機で確認する(FR-008) |
| 修飾キーなしの 1 文字が、入力中や自動マスキングの確認中に誤って効く | 中 | 既存の入力欄の判定を使い、IME 変換中・設定画面・確認モードで止める(FR-013)。E2E で入力中に文字が入ることを確かめる |
| 縮めてコピーで、細い線・小さい文字・モザイクの見え方が変わる | 低〜中 | 縮めるのはコピーだけで、編集は元の解像度のまま(FR-012)。モザイクの読めなさを実機で確認する |
| 画面の倍率が画像から分からない場合がある | 低 | 分からないときは縮めない(FR-012)。今の動作と同じ結果になり、悪化しない |
