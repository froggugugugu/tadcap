# チーム定義 — デザインシステム

## 概要

デザインシステムの定義・監査・UI整合性の確保を専門的に行うチーム。デザイントークンの策定、フィーチャー間のデザイン整合性監査、Apple HIG準拠のUI一貫性チェック、個別UIのレビュー・実装を一貫して担う。**既存画面の横断監査や、新規デザインシステムの立ち上げに最適。**

## 使い方

```text
.claude/teams/TEAM_DESIGN.md <対象範囲 or デザイン指示>
```

引数は省略可能。省略時はPLが対話的に対象を特定する。

### 例

```text
# システム全体のデザイン整合性監査
.claude/teams/TEAM_DESIGN.md システム全体のデザイン整合性を監査・修正

# 特定フィーチャーのUI改善
.claude/teams/TEAM_DESIGN.md src/features/touring/ のUIをデザインシステムに準拠させる

# デザイントークンの定義
.claude/teams/TEAM_DESIGN.md プロジェクトのデザイントークンを定義する

# 監査 + 自動修正
.claude/teams/TEAM_DESIGN.md デザイン整合性を監査し、機械的に修正可能な箇所を修正

# HIG準拠チェック（ボタン・アイコン・用語の一貫性）
.claude/teams/TEAM_DESIGN.md システム全体のHIG準拠・UI一貫性をチェック・補正

# 引数省略
.claude/teams/TEAM_DESIGN.md
```

## チーム構成

| 役割 | エージェント種別 | モデル | 使用スキル | 権限 |
| --- | --- | --- | --- | --- |
| **PL（リーダー）** | general-purpose | Opus | — | delegate |
| **DSエンジニア** | general-purpose | Sonnet | `design-system-audit` | plan必須（PLが承認） |
| **HIGスペシャリスト** | general-purpose | Sonnet | `hig-compliance` | plan必須（PLが承認） |
| **UI/UXデザイナー** | general-purpose | Sonnet | `ui-ux-design` | plan必須（PLが承認） |
| **レビュアー** | general-purpose, mode: plan | Sonnet | `code-review` | plan必須（PLが承認）、ソースコード変更不可 |

### スキルカバレッジ（4スキル）

| スキル | 担当 |
| --- | --- |
| `design-system-audit` | DSエンジニア |
| `hig-compliance` | HIGスペシャリスト |
| `ui-ux-design` | UI/UXデザイナー |
| `code-review` | レビュアー |

## 各役割の責務

### PL（リーダー）

- デザイン作業のスコープ（全体監査 / 特定フィーチャー / トークン定義 / HIG準拠チェック）を決定する
- TaskCreateでタスクリストを作成し、依存関係を設定する
- DSエンジニア・HIGスペシャリスト・UI/UXデザイナーの成果物の整合性を確認する
- デザイン判断が必要な項目について方針を決定する
- **自分でデザイン作業を行わない**

### DSエンジニア

- デザイントークンの定義・検証を行う（スペーシング・タイポグラフィ・コンポーネントサイズ）
- フィーチャー間の横断的なデザイン整合性を監査する
- 使用スキル: `/design-system-audit`
- 監査レポートを `output/reports/review/` に出力する
- `--fix` モードでトークン違反の機械的修正を実施する
- 修正後にビルド・lint・テストを実行して破壊的変更がないことを確認する

### HIGスペシャリスト

- Apple Human Interface Guidelines に基づくシステム横断のUI一貫性をチェック・補正する
- ボタンキャプション・アイコン・用語・ナビゲーションパターンの統一を担当する
- 使用スキル: `/hig-compliance`
- UI用語集（`docs/ui-glossary.md`）の生成・メンテナンスを行う
- `--fix` モードでキャプション・アイコンの機械的統一を実施する
- 修正後にビルド・lint・テストを実行して破壊的変更がないことを確認する

### UI/UXデザイナー

- DSエンジニア・HIGスペシャリストの監査結果に基づき、個別UIの修正・改善を実装する
- パターン不一致・欠落など設計判断が必要な修正を担当する
- 使用スキル: `/ui-ux-design`
- ダークモード・アクセシビリティ・レスポンシブ対応を保証する
- 新規コンポーネントのデザインシステム準拠を確保する

### レビュアー

- DSエンジニア・HIGスペシャリスト・UI/UXデザイナーの変更に対してコードレビューを実施
- 使用スキル: `/code-review`
- デザインシステム準拠・HIG準拠・コード品質の三面を検証する
- **ソースコードは変更しない**

## ワークフロー

```text
PL: スコープ決定 → タスクリスト作成・割り当て
  |
  v（並行可能）
  +-- DSエンジニア: /design-system-audit で監査実行 → トークン監査レポート提出
  +-- HIGスペシャリスト: /hig-compliance で監査実行 → HIG準拠レポート提出
  |
  v
PL: 両監査レポートレビュー → 修正方針決定（機械的修正 vs 設計判断必要）
  |
  v（並行可能）
  +-- DSエンジニア: --fix でトークン違反の機械的修正
  +-- HIGスペシャリスト: --fix でキャプション・アイコン統一の機械的修正
  +-- UI/UXデザイナー: /ui-ux-design でパターン不一致・欠落の修正（設計判断が必要な箇所）
  |
  v
レビュアー: /code-review で変更レビュー → フィードバック
  |  （指摘がある場合は修正 → 再レビュー）
  v
PL: 最終確認 → 完了判定
```

### 依存関係ルール

| 前提条件 | 次のステップ |
| --- | --- |
| PLのスコープ決定 | DSエンジニア・HIGスペシャリストが並行で監査開始 |
| 両監査レポート完成 | PLが修正方針決定 |
| 修正方針決定 | DSエンジニア・HIGスペシャリスト・UI/UXデザイナーが並行修正 |
| 修正完了 | レビュアーがコードレビュー |
| レビュー承認 | PLが最終確認 |

### DSエンジニアとHIGスペシャリストの棲み分け

| 観点 | DSエンジニア | HIGスペシャリスト |
| --- | --- | --- |
| **対象** | 数値（色・余白・サイズ） | 振る舞い・用語・構造 |
| **基準** | プロジェクトのデザイントークン | Apple HIG + UI用語集 |
| **検出例** | ハードコード色値、Tailwind任意値 | ボタンキャプション不一致、アイコン欠落 |
| **修正性質** | トークンへの置換 | ラベル・アイコンの統一 |

両者は並行実行可能で、修正対象が重複することは基本的にない。

## 成果物

| 成果物 | 担当 | 出力先 |
| --- | --- | --- |
| デザイン整合性監査レポート | DSエンジニア | `output/reports/review/DESIGN_AUDIT_{YYYYMMDD}.md` |
| HIG準拠チェックレポート | HIGスペシャリスト | `output/reports/review/HIG_COMPLIANCE_{YYYYMMDD}.md` |
| UI用語集 | HIGスペシャリスト | `docs/ui-glossary.md` |
| デザイントークン定義 | DSエンジニア | `docs/development-patterns.md` のデザインシステムセクション |
| UI修正 | UI/UXデザイナー | `src/` 配下のコンポーネント |
| コードレビュー結果 | レビュアー | `output/reports/review/` |

## 完了条件

- [ ] DSエンジニア: デザイン整合性監査完了、HIGH不整合が0件（修正済み or 方針決定済み）
- [ ] HIGスペシャリスト: HIG準拠チェック完了、MUST指摘が0件（修正済み or 方針決定済み）
- [ ] HIGスペシャリスト: UI用語集（`docs/ui-glossary.md`）が最新状態
- [ ] UI/UXデザイナー: 割り当てられた修正完了、ダークモード・a11y確認済み
- [ ] レビュアー: コードレビュー完了、MUST指摘が0件
- [ ] PL: ビルド・lint・テスト全パス確認
- [ ] PL: 推奨アクション（人間の判断が必要な項目）を一覧化して提示
