# Git 操作・コミット規約

> **always-on rule**: `paths:` を持たないため全セッションで自動 load される(コミットは常に発生しうるため意図的)

> CLAUDE.md 肥大化防止のため切り出したルール。上の frontmatter に従って自動 load され、必要な skill からは `@import` でも明示参照できる。

## Git 操作ポリシー

- `--no-verify` は禁止(フックを迂回しない)
- `--force` は原則禁止(必要な場合は理由を明示し確認を取る)
- フック失敗時はエラーの原因を修正する(フックを無効化しない)
- Git Hooks の構成は `project-config.md` セクション 9 に定義

## コミットメッセージ規約(Conventional Commits)

Release Please によるバージョン自動管理のため、**全コミットメッセージに Conventional Commits プレフィックスを必須**。

| プレフィックス | 用途 | バージョン変化 |
| -------------- | ---- | -------------- |
| `feat:` | 新機能追加 | minor (0.x.0) |
| `fix:` | バグ修正 | patch (0.0.x) |
| `docs:` | ドキュメントのみ | なし |
| `style:` | コードスタイル(動作に影響しない) | なし |
| `refactor:` | リファクタリング(機能変更なし) | なし |
| `perf:` | パフォーマンス改善 | なし |
| `test:` | テスト追加・修正 | なし |
| `chore:` | ビルド・設定・CI等 | なし |
| `ci:` | CI 設定変更 | なし |
| `build:` | ビルドシステム・依存関係の変更 | なし |
| `revert:` | 以前のコミットの取り消し | なし |
| `feat!:` または BREAKING CHANGE | 破壊的変更(後方互換なし) | **major (x.0.0)** |

### ルール

- 形式: `<type>: <日本語の簡潔な説明>`(例: `feat: ダッシュボードページを追加`)
- スコープは省略可: `feat(map): ルート描画を実装` も可
- 破壊的変更: `feat!:` または本文に `BREAKING CHANGE:` を記載
- 1 コミット 1 プレフィックス。複数種類の変更は分割してコミットする
- PR タイトルも同じ規約に従う
