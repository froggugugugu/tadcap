# `/brainstorm` — `/prd` 前段の Socratic ブレスト

## 前提条件

- 要求メモが `input/requirements/<file>.md` に存在する、または対話で 1 文の起点を渡せる状態
- `output/brainstorm/` への Write 権限が設定されている(`settings.local.json` で許可)
- `/prd` をまだ起動していない(本 skill は `/prd` の**上流**)
- 適用条件: メモが半ページ未満 / 「やらない事項」が未明示 / ステークホルダー or 成功指標が不明
  のいずれかに該当(参考: `.claude/learnings/L0001-brainstorm-before-prd.md`)

## 基本姿勢

- **質問駆動**: 推測で機能を膨らませない。曖昧さは `AskUserQuestion` で具体化する
- **コード・ドキュメント変更禁止**: 本 skill の責務は「前提の構造化」のみ
- **Socratic ペース**: 1 ラウンド最大 4 問、最大 3 ラウンドで打ち切り(ユーザー疲弊防止)

## 使い方

### 例

```text
/brainstorm input/requirements/REQ_subscription.md
/brainstorm サブスク機能を追加したい(1 文)
```

### 出力先

- `output/brainstorm/BRAINSTORM_<topic>_<YYYY-MM-DD>.md` のみ
- 他ディレクトリへの Write は不可

### 他スキルとの連携

- 後段(必須): `/prd <出力ファイル>` — 整理結果を起点に正式 PRD 作成
- 並行(任意): `/adr <タイトル>` — 大きな設計判断が出たら記録
- 前段: なし(PRD パイプラインの最上流)

## ワークフロー

1. **入力読込**: 要求メモを Read。または対話で 1〜2 文の起点を聞く
2. **Socratic 質問の連射**(`AskUserQuestion`、1 ラウンド最大 4 問、最大 3 ラウンド):
   - 動機(なぜ今か?1 ヶ月後でも価値があるか?)
   - ユーザー(主たるペルソナ?ニッチケースは?)
   - 成功条件(リリース後どうなれば成功?計測指標は?)
   - やらない(意図的にやらないことは?なぜか?)
   - 撤退(失敗したらどう戻す?データは?)
   - 制約(法務・セキュリティ・SLA で外せない制約は?)
   - 代替案(同じ価値を別の方法で実現できないか?)
3. **暗黙の前提を顕在化**: 「【前提】」マーカーで明示
4. **やる/やらない境界の 3 案提示**: Minimum / Standard / Ambitious
5. **未解決質問のリスト化**: `/prd` 起動前に解消すべきものに ★ を付与
6. **保存**: `output/brainstorm/` に書き出し、ユーザーに提示
7. **ゲート判定**: `/prd` に進んでよいか?を最後に問う(下記「ゲート」参照)

## 出力契約

`output/brainstorm/BRAINSTORM_<topic>_<YYYY-MM-DD>.md` は次のセクションを必ず含む:

```markdown
## 1. 要求の核(一文)
## 2. 前提の棚卸し(明示・暗黙の両方)
## 3. ステークホルダーと利害(誰が何を期待し、何を恐れるか)
## 4. やる/やらない境界の候補(3 案以上)
## 5. 未解決の質問リスト(優先度 ★ 付き)
## 6. 次のステップ(`/prd` を実行できる状態か?)
```

## 禁止事項

- **コード・テスト・本番ドキュメントの変更**(`docs/`, `src/`, `tests/` 不可)
- **要件膨張**: 入力メモにない要件を勝手に追加しない
- **出力先逸脱**: `output/brainstorm/` 以外への Write
- **質問疲弊**: 1 ラウンド 5 問以上、または 4 ラウンド以上の質問
- **シークレットの転記**: 発見した API key 等は `[REDACTED]` で隠す

## ゲート

- **ゲート 1**: ブレスト完了時に「`/prd` に進める状態か?」をユーザーに問う
- **ゲート 2**: 未解決の ★ 付き質問が 3 件以上残っている場合は `/prd` への遷移を保留する
  (ユーザーが明示的に「進めて」と指示した場合のみ通過)

## 想定される質問テンプレート

| カテゴリ | 質問例 |
| -------- | ------ |
| 動機 | なぜ今これをやるのか? 1 ヶ月後でも同じ価値があるか? |
| ユーザー | 主たるユーザーペルソナは? ニッチケースは誰か? |
| 成功条件 | リリース後どうなれば成功? 計測指標は? |
| やらない | 意図的にやらないことは何か? なぜか? |
| 撤退条件 | 失敗が判明したらどう戻すか? データは? |
| 制約 | 法務・セキュリティ・SLA で外せない制約は? |
| 代替案 | 同じ価値を別の方法で実現できないか? |
